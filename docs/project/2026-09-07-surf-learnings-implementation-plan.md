## 5. Key risks and mitigations

- Operator decisions not yet confirmed (§0): each slice that encodes one names its fallback; S5 commit (3) and S6 commit (3) are the two that would change shape, and both are single revertable commits.
- Shared checkout: another session holds uncommitted edits in `AGENTS.md`, `package.json`, `scripts/install-hooks.sh`, `docs/dev/EXTENSION_SOP.md` and the deletion of `scripts/docs-list.sh`; the architecture review itself is still untracked. Never `git add -A`, never `git add .`, never stage those paths. Before every commit `git diff --cached --stat` must list only this slice's files. `package.json` is edited by S2, S6, S10 while the other hunks are pending: stage only our hunks by building the index blob from HEAD (`git show HEAD:package.json > <scratch>/package.json`, apply our edit there, `git update-index --add --cacheinfo 100644,$(git hash-object -w <scratch>/package.json),package.json`), then verify with `git diff --cached -- package.json` that the `docs:list` lines are absent. If the other session commits first, the trick is unnecessary; check `git status --short` at the start of each slice.
- `spawnStep` collapse (S3) touches every runner at once: kill-tree and output-cap semantics of `CliTesterAgent.runCommand` and Bombadil's two spawn sites must be preserved; the existing `bombadil_runtime_contract` and `runtime-diagnostic:corpus` lanes are the regression net, and commit (2) of S3 is revertable on its own.
- Browser flakiness: `npm test` never touches a browser (fake-surf, fake-agent-browser, fake CDP, all fed by captures). Live runs are dogfood, recorded in `*-live-run.md`, never a gate; each uses owned tabs, records `tab.list` before and after, and no login. A failing dogfood is investigated and rerun by hand, never wrapped in a loop.
- Fixture fidelity: the fake learns only from `tests/fixtures/captures/` (A17) and a fidelity test pins it; coverage of `surf-client.ts` still measures the fake, and the plan never cites coverage as live evidence.
- Ratchet baselines across Node majors: workstation Node 26.8.1, CI Node 22, no local 22. Floors keyed by major from the start; `--raise` only touches the running major; CI's first run appends `"22"`; a red that is about the machine is a bug in the gate, not a reason to widen the 0.005 tolerance.
- Public API break (S6): removing `type({submit})`, requiring `evaluate(code, {effect, reason})`, deleting `SurfFlowBuilder`; 0.4.0 with `consumer:smoke` proof and the README release note.
- Behaviour changes that make existing configs fail: S4 `empty` refusal and `expect.output: required` default; S5 Bombadil refusing outside `mutation.allowOrigins` and mutating operations refusing on an unwritable `receipts.dir`. Intended; every refusal names the config line that fixes it (A16) and the release note lists them.
- Interlock scope: per `receipts.dir`; CI without a persistent path is not interlocked, and `docs/api/config.md` says so (review Lens 3e).
- `truth:gate` passport byte-identity and the overclaim grep: every surface change regenerates the passport in the same commit; S8 re-reads the grep before adding `frame_boundary`.
- Token/time budget: natural stopping points after S2 (gate installed), S4 (classification live), S6 (mutation safety and the session seam complete). Each L slice has three or four commits so a partial slice still leaves `main` green.

## 6. Rollout and rollback per slice

Every slice is one to four commits on `main` that `git revert` cleanly; later slices depend on earlier ones by import only, so reverting S<n> requires reverting S>n first (dependency order in §2). New config keys (`expect`, `receipts`, `mutation.allowOrigins`, `surf.submit.*`, `observation`) are optional with fail-closed defaults; new CLI flags are additive; new envelope fields (`outcome`, `outcomes`, `bases`, `effect`, `mutations`, `runId`, `observations`, `frameRootCause`) are additive; the only removals are the S6 public-API ones, reverted by reverting S6 commit (3). Ratchet floors are introduced at measured truth (S2) and raised only by `--raise` after measurement (S10), never edited upward by hand; a floor drop is a `reductions` ledger entry in the same commit; `allowed_cycles` starts empty and any new cycle needs a ledger entry. `receipts.dir` is never deleted by code; deleting it is documented as an interlock reset with the standing of `--supersede-receipt`. Live-run docs are additive files; a slice's dogfood failure blocks only that slice's final commit. Old receipts do not exist, so there is no receipt migration; heal artifacts v1 are unchanged and `--findings-input` accepts legacy findings.
