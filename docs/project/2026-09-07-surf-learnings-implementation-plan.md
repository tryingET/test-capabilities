## 1. Scope and non-goals

In scope (what the amended packets commit to, plus the adjudication's kernel objects):
- Kernel, pure ring (exported, imports neither `node:fs` nor `node:child_process`; the ring is an import rule the structure check enforces, not a directory): `RawResult`, `classifyResult`, `ResultOutcome` with `basis` incl. `indeterminate`, `Determination` (frame and run verdict), `Expectation` with `declaredBy` incl. `author:`, effect classes and the `EffectStep` types, `error-codes.ts` + `FrameworkError`, `config.ts` (D4).
- Kernel, mediated ring (the only code that touches the world): `RunContext {runId, startedAt, config, receiptStore, ledger, adapters}`, `MutationLedger.runStep` as the sole mutating caller of `Adapter.invoke`, `ReceiptStore {append, list}` with files under `receipts.dir` as v1 through `artifacts.ts` (fsync, 0600), `Session {open, gate, step, observe, close}` as a kernel interface, `Adapter {resolve, probe, translate, effects, invoke, normalize}` with `spawn-step.ts` as the spawn transport.
- Adapters: surf (implements `Session`; explore, plan, apply and both observers are step lists), bombadil (one mutating/target step, typed status, under `mutation.allowOrigins`), agent-browser (observe steps, HTTP invoke for `/json/*`, spawn invoke for `snapshot`), http (row reserved).
- P1 mutation safety, P2 submit gate, P3 frame root cause, P4 quality ratchet, P5 result classification, P6 a11y channel as amended (see each packet's decision log); the four agents become step lists under `src/core/operations/test/agents.ts`; correlation and root cause stay in the orchestrator as a diagnosis consumer that never sets `ok`.

Explicitly deferred, by name: `SideEffectWitness` (network, navigation and DOM witness around read-only steps); the in-frame positive probe (P3 open question 5; `frame.switch`/`frame.main` are now `browser_session` scope); `within` landmark scoping and a structured a11y producer (P6); the http adapter; exit code 2 for the third state (D3); a shared `Spec` artifact for LLM-authored replayable tests; a persistent CI receipt store (D5 refuses instead); the `src/core/kernel/` and `src/core/adapters/` directory move; the surf-cli upstream `form.plan`/`form.apply` proposal (P2 D7); a cross-run receipt index; per-click Bombadil receipts; `--verify-js` per field; mutation score (screening lane); deleting the quantum route or the prediction exports (D1 keeps them parked).

Never `git add -A` or `git add .`; never stage those paths; `git diff --cached --stat` before every commit lists only this slice's files. `package.json` is edited by S1b, S2, S10: stage only our hunks by building the index blob from HEAD (`git show HEAD:package.json > <scratch>/package.json`, apply our edit, `git update-index --add --cacheinfo 100644,$(git hash-object -w <scratch>/package.json),package.json`) and verify with `git diff --cached -- package.json` that the `docs:list` lines are absent. `scripts/install-hooks.sh` does not reference `scripts/test-agent-browser.sh`, so S1's deletion does not collide with the other session's hunk.
- Removals before floors (S1b): the deleted exports may be used by a consumer this repo cannot see; `consumer:smoke` covers the packed surface and the 0.4.0 release note names every removed symbol with its replacement (`Session`).
- D1 parked code inside the runtime: the risk is that quantum or prediction output leaks into a verdict through a future edit; `tests/parked_runtime_contract.test.mjs` pins it, and the ratchet excludes the directories so their coverage cannot mask erosion elsewhere.
- `Adapter.invoke` collapse (S3) touches every runner at once; kill-tree and output-cap semantics are preserved by the `bombadil_runtime_contract` and `runtime-diagnostic:corpus` lanes, and S3 commit (2) reverts on its own.
- Ephemeral detection (D5) false positives on a developer's `$TMPDIR` checkout: the refusal names `receipts.ephemeral: true` and `receipts.dir`; `doctor` shows what it detected and why.
- Browser flakiness: `npm test` never touches a browser (fakes fed by captures); live runs are dogfood, recorded, never gating; owned tabs, `tab.list` before and after, no login; a failing dogfood is rerun by hand, never in a loop.
- Ratchet across Node majors: floors keyed by major; `--raise` only on the running major; CI appends `"22"`; a machine-caused red is a gate bug, not a tolerance change.
- Behaviour changes for existing configs: S4 `empty` refusal and `determination: unverified`; S5 Bombadil outside `mutation.allowOrigins`, unwritable or ephemeral `receipts.dir`. Intended; every refusal names its fix (A16); the release note lists them.
- `truth:gate` byte identity and the overclaim grep: regenerate the passport in every surface-changing commit; S8 re-reads the grep before `frame_boundary`.
- Token/time budget: stopping points after S1b (0.4.0 published with removals only), S2 (gate installed), S4 (determination live), S6 (session and mutation safety complete). Each L slice has three or four independently revertable commits. Use the peer-model rule in §3 before spending a session on a stuck design question.

## 6. Rollout and rollback per slice

Every slice is one to four commits on `main` that `git revert` cleanly; later slices depend on earlier ones by import only, so reverting S<n> requires reverting S>n first. 0.4.0 is published at S1b with the removals only, so a partial later slice never leaves a half-removed API. New config keys (`expect`, `receipts.{dir,ephemeral}`, `mutation.allowOrigins`, `surf.submit.*`, `observation`) are optional with fail-closed defaults; new flags and envelope fields (`outcome`, `determination`, `outcomes`, `bases`, `effect`, `mutations`, `runId`, `observations`, `frameRootCause`) are additive; the removals are S1b (exports) and S6 commit (3) (`surf-client.ts`), each one commit. Floors are introduced at measured truth after S1b and raised only by `--raise` in S10; a floor drop is a `reductions` ledger entry in the same commit; `allowed_cycles` starts empty. `receipts.dir` is never deleted by code; deletion is documented as an interlock reset with the standing of `--supersede-receipt`. Live-run docs are additive; a dogfood failure blocks only that slice's final commit. Heal artifacts v1 are unchanged and `--findings-input` accepts legacy findings; `test --json` stays parseable throughout.
