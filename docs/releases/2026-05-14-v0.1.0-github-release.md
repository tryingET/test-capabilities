# GitHub release draft — v0.1.0

## Title

test-capabilities v0.1.0 — first public alpha

## Release body

`test-capabilities` v0.1.0 is the first public alpha of the fail-closed testing capability framework.

This release is intentionally scoped around one polished zero-external-dependency path: **CLI smoke + observation diagnostics**. It is useful today for proving a package/runtime setup, generating a minimal config, running a safe CLI smoke target, and inspecting structured diagnostic output. Browser/property exploration, healing, and root-cause synthesis are present but should be treated as bounded alpha surfaces.

### Supported in this alpha

- `test-capabilities doctor`
  - verifies required package/runtime/config basics
  - checks CLI target executability without running the target
  - reports missing Surf Go or Bombadil-compatible runtimes as optional warnings
- `test-capabilities init`
  - generates a minimal fail-closed `test-capabilities.yaml`
  - enables only the supported `cli-tester` path by default
  - refuses overwrites unless `--force` is provided
- `test-capabilities demo`
  - runs the packaged `examples/demo/cli-demo.mjs` fixture
  - proves the zero-external `cli-smoke-observation` path
- `test-capabilities test --json`
  - emits the primary machine-readable operation envelope for agents and CI
  - supports the `cli-tester`, `surf`, and `bombadil` orchestrator agents when their runtime requirements are satisfied
- `test-capabilities surf explore`
  - supports bounded Surf Go-backed exploration with explicit browser-state/DOM probes
- `test-capabilities quantum`
  - runs the bounded simulator path for explicit URL targets
- `test-capabilities heal`
  - proposes and applies reviewable selector repairs; apply mode requires an external `--checkpoint-ref`
- diagnostic observations
  - supported agents emit `observation.v1` entries
  - calibrated `root_cause` and low-calibration non-authoritative `propagation` observations are available when correlation has enough bounded evidence

### External runtime requirements

The first-run path does **not** require external browser/property tools:

```bash
test-capabilities doctor --json
test-capabilities demo --json
```

Optional advanced integrations require external runtimes:

- Surf-backed exploration requires `surf-go`, `TEST_CAPABILITIES_SURF_GO_BIN`, or a source checkout referenced by `TEST_CAPABILITIES_SURF_GO_REPO`.
- Bombadil-backed exploration requires `TEST_CAPABILITIES_BOMBADIL_BIN`, a built source checkout referenced by `TEST_CAPABILITIES_BOMBADIL_REPO`, or `bombadil` on `PATH`.
- Packed npm consumers should treat Bombadil-compatible tooling as external; the package intentionally excludes repo-local `external/bombadil`.

### Explicitly unsupported / fail-closed

These surfaces are not shipped as working product behavior in v0.1.0 and fail clearly when invoked or enabled:

- autonomous testing flags such as `--autonomous`
- self-healing orchestration flags such as `--self-heal`
- prediction CLI support via `predict` or `--predict`
- `visualize` and `report` CLI commands
- `api-fuzzer` orchestrator agent
- `self_healing`, `prediction`, and `collective` orchestrator intelligence modes
- chaos execution
- Surf actions beyond the supported `explore` path, such as `flow`, `assert`, `compare`, and `replay`

### Important alpha caveats

- This is an alpha release, not a stable production QA platform.
- Root-cause and propagation observations are evidence-bounded diagnostics, not causal proof, prediction, or repair-order authority.
- The root-cause corpus is deterministic fixture proof, not broad empirical validation.
- Surf Go and Bombadil-compatible integrations depend on external runtime availability and version behavior.
- Vision docs describe future direction; the README and `docs/api/*` are the current runtime contract.

### Quick start

```bash
npm install -g test-capabilities

test-capabilities doctor --json
test-capabilities init --output test-capabilities.yaml --target node
test-capabilities demo --json
test-capabilities test --config test-capabilities.yaml --quick --json
```
