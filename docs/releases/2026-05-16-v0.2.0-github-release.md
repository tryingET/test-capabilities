# GitHub release draft — v0.2.0

## Title

test-capabilities v0.2.0 — Bombadil 0.5 integration

## Release body

`test-capabilities` v0.2.0 expands the Bombadil-backed alpha surface while keeping the package fail-closed and honest about external runtime requirements.

### Added

- Bombadil 0.5 browser-test config support:
  - request headers
  - trace output paths
  - trace reproduction
  - viewport, instrumentation, and permission knobs
  - `test-external` debugger settings
- Experimental `terminal-fuzzer` orchestrator agent:
  - runs `bombadil terminal test -- <command> [args...]`
  - supports typed `agents.<name>.terminal` config
  - emits normalized `observation.v1` runtime evidence for CLI/terminal targets
  - fails closed on missing Bombadil or missing target command
- Public Bombadil 0.5 adoption guide.
- Documented Bombadil distribution posture: Bombadil remains an external binary requirement for packed consumers.

### Changed

- Release workflow/docs now continue to use the `ts-quality` style: GitHub Release is the single public release intent; npm Trusted Publishing/OIDC performs publication.
- Bombadil docs now explicitly recommend upstream release binaries for verification when local source builds need unavailable prerequisites such as Zig/Nix shell support.
- Product posture and API/config/type docs now include the bounded terminal-fuzzer support boundary.

### External runtime requirements

The zero-external first-run path remains:

```bash
test-capabilities doctor --json
test-capabilities demo --json
```

Optional integrations require external tools:

- Surf-backed exploration requires `surf-go`, `TEST_CAPABILITIES_SURF_GO_BIN`, or a source checkout referenced by `TEST_CAPABILITIES_SURF_GO_REPO`.
- Bombadil-backed browser and terminal-fuzzer agents require `TEST_CAPABILITIES_BOMBADIL_BIN`, a built source checkout referenced by `TEST_CAPABILITIES_BOMBADIL_REPO`, or `bombadil` on `PATH`.
- Packed npm consumers should treat Bombadil-compatible tooling as external; the package intentionally excludes repo-local `external/bombadil`.

### Explicitly unsupported / fail-closed

These surfaces are still not shipped as working product behavior and fail clearly when invoked or enabled:

- autonomous testing flags such as `--autonomous`
- self-healing orchestration flags such as `--self-heal`
- prediction CLI support via `predict` or `--predict`
- `visualize` and `report` CLI commands
- `api-fuzzer` orchestrator agent
- `self_healing`, `prediction`, and `collective` orchestrator intelligence modes
- chaos execution
- Surf actions beyond the supported `explore` path, such as `flow`, `assert`, `compare`, and `replay`

### Important alpha caveats

- This remains an alpha release; use `--prerelease` on the GitHub Release unless intentionally promoting to latest.
- The terminal-fuzzer slice is bounded experimental evidence, not a production terminal-autonomy or stability claim.
- Root-cause and propagation observations are evidence-bounded diagnostics, not causal proof, prediction, or repair-order authority.
- Surf Go and Bombadil-compatible integrations depend on external runtime availability and version behavior.

### Quick start

```bash
npm install -g test-capabilities@0.2.0

test-capabilities doctor --json
test-capabilities demo --json
```

For Bombadil 0.5 adoption, see `docs/adoption/bombadil-0.5-how-to.md`.
