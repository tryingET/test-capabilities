# test-capabilities v0.4.0

These notes cover the complete source line since published **v0.3.0**, not just the final
transport repairs. They are release preparation; they do not record a published tag,
registry upload, deployment or receiver acceptance.

## Compatibility: migrate before upgrading

- **Legacy exports removed:** `SurfClient`, `SurfFlowBuilder`, their retired Surf-specific
  types, `createNexus`, `NexusOrchestrator`, `NexusConfig` and the default export are absent.
  Use named `createTestCapabilities` / `TestCapabilitiesOrchestrator` imports and the
  `Session` / `SurfSession` browser scope. The
  [export inventory](https://github.com/tryingET/test-capabilities/blob/v0.4.0/docs/api/exports.generated.md)
  is the exact package surface.
- **Retired Surf runtime:** migrate off surf-go and its environment selectors. Surf integration
  uses nicobailon/surf-cli with the required readiness/extraction mechanisms (v2.20.0 or later
  with the advertised commands). Runtime probing fails closed when mechanisms are absent.
- **Evidence, not process success:** a silent exit-zero CLI response is unverified unless the
  caller explicitly declares empty output meaningful. Result envelopes add typed outcomes,
  basis/determination, run identity, effect declarations and mutation receipts. Existing
  `passed` remains, but no-evidence and indeterminate outcomes are not passes.
- **Mutating work needs declared authority:** name allowed origins in config, use reviewed
  content-bound plans/approvals where required, and keep receipts on durable storage. A CI
  workspace, temporary directory or disposable worktree is not durable by default. Explicit
  `receipts.ephemeral: true` accepts that limitation; package verification uses it only for
  bounded fixtures, not as production deployment guidance.
- **No uncertain replay:** interrupted/unknown mutation receipts block the same key. Inspect
  the actual target before any separately authorized receipt supersession; do not delete
  history to make a retry pass.
- **Low-level CDP scripts:** two-argument `CdpActions.evaluate` calls remain callable, but
  arbitrary/mutating scripts are not automatically repeated after context loss in either
  world. Only a genuinely pure read may opt in with the optional third argument
  `"read_only"`. Execution-world isolation is not purity or mutation authorization.

See [README migration](https://github.com/tryingET/test-capabilities/blob/v0.4.0/README.md#what-an-existing-03x-setup-has-to-change)
and [type reference](https://github.com/tryingET/test-capabilities/blob/v0.4.0/docs/api/types.md).

## Source capabilities in this line

### Evidence and controlled effects

- Typed operation routes, adapter/transport boundaries and a single owned browser-session
  scope replace legacy wrapper authority. Mutating steps write receipts before dispatch;
  unknown outcomes retain replay interlocks.
- Bounded selector healing uses guarded writes, precondition/after hashes and receipt-limited
  compensation. An external checkpoint reference does not grant this package restore authority.
- Replacement-validation requests and schemas preserve source-owner/receiver boundaries;
  behavior observations do not grant dependency removal, promotion or deployment authority.
- `observation.v1` supports diagnostic synthesis/correlation, evidence-bounded current
  failure classes and explicitly low-calibration heuristic propagation. Prediction and
  autonomous repair are not implied by a diagnostic label.

### Browser surfaces

- Owned-target CDP accessibility observations replace the retired agent-browser observation
  producer without claiming tab restoration. Frame-aware actions/diagnosis, same-process
  frames, explicit document/target pins and open-shadow paths have bounded contracts.
- `surf plan` / `surf apply` and bounded `surf flow` separate read preparation, reviewed
  content-bound execution and receipted acts. Submit is explicitly authorized and at most
  once for its key; ambiguous effects are never automatically repeated.
- Persistent Surf transport is optional when the producer advertises it; older/unsent
  startup cases retain controlled CLI fallback. Sent loss revokes session ownership/readiness
  and requires explicit new owned-page/session initialization, not automatic rebind.
- Teardown awaits bounded native close completion and still attempts owned cleanup after
  secondary failures. Native close timeout is not forced socket teardown; a preparation
  deadline does not establish background quiescence.
- Malformed stdio JSON/shapes cannot escape a callback or falsely acknowledge/refuse a
  pending mutation. Sent corruption/loss remains unknown; queued work cannot escape revoked
  ownership through fallback.
- Context acquisition is separate from script execution. Context-error recovery cannot
  replay an arbitrary/mutating body or mask its first possible-execution failure as an
  unsent refusal. Explicit reads retain bounded recovery and original causes.

### Diagnostic and quality repairs

- The real-subprocess mixed-evidence corpus works under a genuinely Node-only PATH without
  assuming `mkdir` or `sleep` exists there. Budgets and diagnostic guard assertions remain;
  it checks one intended exit failure and one framework-enforced timeout in either agent order.
- Ordinary `durationMs` measurements no longer supply latency evidence by themselves.
  Explicit timing signals/comparators and actual timeouts remain supported; the existing
  diagnostic method is textual and bounded, not arithmetic or causal proof.
- Contract-sync checks runtime/CLI/schema/export drift; coverage and source-structure
  budgets retain their floors. Root-only generated `.ontology/` and scratch `.tmp/` scan
  exclusions do not hide similarly named source directories or rewrite generated evidence.
- Standardized `Justfile` commands preserve npm-owned behavior. Product CI removes redundant
  outer build work while retaining distinct ordinary, instrumented and packed-consumer proofs.

## Distribution and external requirements

The npm package includes the intended CLI/library, schemas and demo assets, not repository
fixtures, private provider tooling, source maps or vendored external browser binaries.
Zero-external `doctor` / `demo` paths are separate from integrations requiring tools.

- Surf needs a compatible CLI plus the browser/extension runtime; enabling optional producer
  features does not install or accept that runtime.
- Bombadil-compatible browser/terminal-fuzzer paths need an explicitly resolvable external
  binary. Packed consumers receive an honest refusal when it is absent.
- Runtime metadata declares Node >=22. The measured release-building lane is Node 22
  >=22.22.2 with npm 12.0.2. Coverage-floor availability is not a claim that every Node major
  or operating system has received equivalent receiver qualification.

The prepared publisher verifies one intended tarball, binds its source/version and SHA-256
in a manifest, and rechecks the same bytes before file-based OIDC publication and asset
attachment. That source contract does not prove an upload happened or that downloaded
channel bytes match; those checks require the separately authorized publication step.

## Known limits and rollout

- Current source/fixture and package proof is not live-browser crash-canary acceptance,
  restoration of interrupted tests/tabs, or a guarantee of atomic document authorization.
  Read declarations are trusted intent; concurrent already-dispatched work is not canceled.
- Fresh >=30% Surf speed qualification remains separate. Historical timings are not a
  current-build promise, and these notes make no new speed claim.
- Quantum/prediction library surfaces remain parked; prediction flags, autonomous self-heal,
  chaos execution and unsupported agents/actions still fail closed rather than produce fake evidence.
- Browser/audio installation, login/logout recovery and workstation receiver acceptance are
  not granted by package release preparation.
- Existing unknown mutation history must survive upgrades. Do not use a downgrade, reinstall
  or receipt deletion as an automatic recovery step. A corrective package publication needs
  its own version/intent and compatibility assessment.

Before public intent: complete the qualified source/package checks, confirm hosted CI and
private strict-docs-provider access, and verify external Trusted Publisher/Release settings.
GitHub Release publication remains the single public intent and requires separate operator
authorization; this preparation did not push, create a release tag or publish to npm.
